# 检索单独评测，不经过大模型；单元测试用假的向量模型

我们决定：

- 标一套评测题（`evals/policy_questions.jsonl`）：51 道政策里有的题，每道标上应该查到的条款；12 道政策里没有的题，应该拒答。
- 评测脚本只跑检索，不调大模型，结果每次都一样。看两类数字：Recall@4（应该查到的条款有没有进前 4），以及不同阈值下，有政策的题被误拒了几道、没政策的题漏拒了几道。「只用向量」「只用关键词」「两个一起」分别算一遍，用数字决定用哪一种（结果见 ADR 0013）。
- 拒答阈值用这套题来定。
- 单元测试用假的向量模型（每组近义词占一维），不下载模型、不联网。切段、Qdrant、BM25、合并、拒答、工具和接口都是真代码，真模型好不好由评测来说明。

## Considered Options

- **让大模型给回答打分（LLM-as-judge）**：能评整个回答，但慢、花钱、每次结果不一样。检索这一步有标准答案，用不着它。评整个回答放到第 7 步。
- **单元测试里用真模型**：要下载模型、要联网，测试变慢，结果还会随模型版本变化。
- **不评测，凭感觉调**：改了切段、分词或阈值，说不清是变好了还是变坏了。

## Consequences

- 题和政策是同一个人写的，题目的说法会不自觉地贴近政策原文，分数会偏乐观。阈值也是在同一套题上定的，没有单独留一份题来验证。真上线要用真实用户的问题补题。
- 单元测试测不出向量模型本身的好坏，这一块只能靠评测。
