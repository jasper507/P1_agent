# 评测之后默认只用向量检索，关键词合并留成开关

第一次用真模型跑评测（`evals/README.md`），51 道政策里有的题，Recall@4：只用向量 1.00，只用关键词 0.80，两个一起 0.96。合并反而丢了两题：

- 「快递送到了，盒子是破的怎么办」：条款写的是「外包装破损」。分词以后「破」对不上「破损」，「盒子」对不上「外包装」，关键词那一路抓了带「快递」「送到」的条款。
- 「发票什么时候能开出来」：「开出来」切成「开」「出来」，对不上条款里的「开票」「开出」。「发票」在发票政策的每一段里都有，关键词那一路把正确的条款排到了第 10。

这些被抓来的段落在两路里都出现，RRF 给它们加了分，把向量排在前面的正确条款挤出了前 4。反过来，没有一道题是只靠关键词才找到的：问「专票」「运费险」「包邮」的题，只用向量也都排进了前 4。用户说的是口语，政策写的是书面语，关键词对不上的时候比对得上的时候多。

我们决定：

- 默认只用向量检索，按相似度取前 4 条交给模型。
- 关键词检索和 RRF 合并的代码留着，配置 `POLICY_HYBRID=true` 就打开。评测每次都把三种方式各算一遍。政策变了，比如出现型号、编号这类必须一字不差的词，先看评测，再决定开不开。
- ADR 0011 里的切段、向量模型、内存索引和「拒答看向量那一路的最高相似度」不变。

## Considered Options

- **保留混合检索，接受 0.96**：多一路检索、多两个依赖，在这批题上只丢分，不加分。
- **给关键词那一路降权重**：两路都出现的段落优势很大，权重要压得很低才救得回这两题。只有 51 道题，调出来的权重很可能只对这批题有效。
- **往 jieba 词典里加「破损」「开出」这些词**：这是照着丢掉的两题补，换一批说法又会对不上。
- **加重排模型（reranker）**：重排模型把问题和每条候选放在一起判断相不相关，比合并两份名单更准，打的分也更适合拿来拒答。代价是要多下载一个大得多的模型、每次多一轮推理。评测说向量不够用了再加。

## Consequences

- 检索只靠向量模型对意思的理解。真遇到要精确匹配的词（订单号、商品型号），向量可能排不准，到时打开开关、补上对应的评测题再看数字。
- jieba 和 rank-bm25 还留在依赖里，开关和评测都要用。
- 两种方式只差 2 道题，样本很小。但丢题的原因看得清楚，而且没有一道题是反过来靠关键词才找到的。
