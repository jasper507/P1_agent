# 以当前用户自己的登录会话调用商城接口

客服 agent 需要读当前用户的订单。我们决定：agent 不连商城数据库，也不持有服务账号，而是把浏览器带来的 `sessionid` 原样转给商城的公开接口，由商城判断「这是谁、能看哪些订单」。这样权限只在商城一处判断，即使模型被提示注入，agent 能做的也不会超过当前用户本人的权限。

## Considered Options

- **直连商城数据库**：最快，但绕过了商城的权限和业务规则，两个系统会耦合在表结构上。
- **服务账号 + user_id 参数**：agent 拿一个能看所有订单的凭证，靠自己传 user_id 区分用户。user_id 的来源一旦出错（比如模型被诱导），就能查到别人的订单。
- **透传当前用户的会话**（选择这个）：agent 的权限永远等于当前用户的权限。

## Consequences

- agent 必须能收到商城的 cookie：本地开发靠同主机不同端口（cookie 不按端口隔离，RFC 6265 §8.5），上线时要同域名部署，否则得改成 token 交换。
- 用户在商城的登录过期，agent 也跟着返回 401。
- 每次请求都要问一次商城 `/api/auth/me/`，多一次往返。
