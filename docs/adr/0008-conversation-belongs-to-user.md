# 对话属于用户，不属于登录会话；别人的对话一律 404

我们决定：对话编号由服务端生成，存对话时记下所属用户的 id，每次读之前和当前用户比对。对不上、不存在、已过期，都返回同一个 404「对话不存在或已过期」，不告诉对方这个编号是不是真的存在。用户重新登录以后，登录会话变了，但还是同一个用户，可以接着聊。

## Considered Options

- **绑定登录会话**：重新登录就丢了对话；而且要把会话号这种凭证存进 Redis，多一处可能泄露的地方。
- **别人的对话返回 403**：等于承认「这个编号存在，只是不是你的」。商城对别人的订单回 404，这里保持一致。
- **前端自己生成编号**：服务端就分不清「新对话」和「过期的对话」。过期的对话会被当成新的悄悄开始，用户说「第二张呢」，模型手里什么都没有。由服务端生成以后，没带编号就是新对话，带了但找不到就是 404，前端据此提示重新开始。

## Consequences

- 退出登录不会删掉对话，它在 30 分钟后自己过期。
- 拿到别人的对话编号也读不到内容；编号是随机 UUID，只是多一层防护，真正的检查是比对用户 id。
